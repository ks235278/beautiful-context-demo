# Beautiful Context — 動作するプロトタイプ

**公開URL** → https://ks235278.github.io/beautiful-context-demo/

エディターで作ったコンテクストが、そのまま公開ページになり、UniverseIt! の
見出しに現れ、読めるようになります。画面をつないだだけのモックではなく、
データで動きます。

## ホーム画面に追加して開いてください

Safari のタブで開くと、画面上部の 38pt はブラウザのもので、ページからは
描けません（`safe-area-inset-top` が 0 になる）。ホーム画面に追加して
そこから開くと全画面になり、回路の模様が Dynamic Island の裏まで
回り込みます。前田先生の構成図どおりの見え方になるのはこちらです。

> Safari で開く → 共有 → ホーム画面に追加 → ホーム画面のアイコンから開く

## 縦スクロール一本

```
起動画面            BEAUTIFUL CONTEXT。回路の模様が画面いっぱい
   ↓ スクロール      表題が薄れ、入れ替わりに路線図が現れて流れ続ける
路線図              見出しが角度の違う線を走る。ページはここで終わる
   ↓ UNIverseIt!    ボタンを押すと続きが現れ、そのまま送り込まれる
コンテクスト ①      二作品 → 見出し → 関係 → 本文
   ↓ スクロール
コンテクスト ②
```

下部のドックは固定で、読んでいる区間に合わせて路線図が変わります。
見出しをタップするとその区間まで送られ、作品名をタップすると駅の
ページが同じ画面の中で入れ替わります。別ページへは飛びません。

## 画面はひとつ

内容が入れ替わるときは必ず、消えるものが薄れてから現れるものが濃くなります
（`fade.css`）。区間から区間への移動も、跳ぶのではなく送る形にしてあります。
ブラウザの `scroll-behavior:smooth` は途中で打ち切られることがあるため、
自前で送り、指が触れた瞬間に譲ります。

## データの形

エディターが扱う `{a, b, context}` をそのまま1件として保持します。

```js
a / b   : { title, type, year, creator, slug, image, summary }
context : { routeName, label, headline, slug, relation,
            leftStation, rightStation, body }
```

作品は複数のコンテクストに登場できます。駅のページには、その作品が
関わるすべての区間への導線が並びます。

## エディターの使い方

| URL | 動作 |
|---|---|
| `editor.html` | サンプルを読み込む |
| `editor.html?new=1` | 空の状態から作る |
| `editor.html?slug=xxx` | 既存のコンテクストを編集する |

「公開する」で保存し、ストリームのその区間まで移動します。
路線名と作品A・Bの作品名は必須です。

## 地色について

模様が乗った面と無地の面は、同じ色でも濃さが違って見えます。実機の
スクリーンショットから画素を測り、見えている色と地色が一致する値を
解いて `--ground: #141c25` としました。canvas で SVG を描き直して
測った値は Safari の実描画と合わなかったため使っていません。

## 保存先について

データはブラウザの `localStorage` に入ります。したがって —

- 作ったものは**その端末のそのブラウザにだけ**残ります
- 別の端末や別の人には見えません

複数人で同じデータを見るにはサーバーとデータベースが必要です。
本プロトタイプの範囲外としています。

## 実装していないもの

- バックエンド、ログイン、共有データ
- 生成AIによる初稿生成
- 四軸評価エンジン（意外性・共感度・コンテンツ性・世界観近似性）
- 検索ボリューム・広告単価の照会
- ハブを主題とするランディングページ（現在は二作品1組が公開単位）

## 動かし方

`docs/index.html` をブラウザで開くだけで動きます。通信は不要です。

```bash
cd docs
python -m http.server 8788
```
